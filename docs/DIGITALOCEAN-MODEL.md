## Owners and invariants

One failure class: treating requested infrastructure, certificate admission, or recovery as confirmed usable state without evidence from its owner. DigitalOcean owns cloud resource IDs/lifecycle; the root runner alone owns creation/deletion and a private intent/result ledger. The existing installer owns app/instance runtime identity; gateway controller owns atomic confirmed startup JSON; ACME owns certificate issuance; each app owns its database/blobs; Restic owns confirmed encrypted snapshots. No other agent provisions or destroys resources.

- Exact task-created IDs only may be deleted. Preexisting droplets/keys/firewalls/volumes remain untouched. No provider backups, snapshots, reserved IPs, block volumes or Spaces subscriptions are created.
- Provider mutations use zero automatic HTTP retries. Persist intent before mutation; an unknown outcome is reconciled by exact unique name/tag and provider ID, never replayed blindly. Read-only provisioning waits have a 15-minute deadline.
- Each app has its own Droplet, public IPv4, origin, account, database and data volume. Four apps share no session or browser origin. A separate temporary storage Droplet exercises off-app-host loss; a new empty recovery Droplet is provisioned for each successful app recovery, tested and destroyed sequentially (at most six live hosts). One additional unused Chat recovery host may be replaced after the confirmed network-filter failure described below; every resource ID stays in the ledger.
- SSH access uses a new task-owned key. Per-host host keys are generated privately and supplied through authenticated cloud-init, then exactly pinned locally; password login and host-key bypass are forbidden.
- Cloud firewall permits SSH from the observed controller IPv4 /32 and public TCP80/443 for ACME/application access. Docker uses protected default bridge/NAT settings. No Docker/admin/S3 backend ports are publicly published.
- Normal OS/browser CA and IP-name verification is mandatory. No public HTTP authentication, TLS bypass, DNS aliases or fabricated public-provider proof.
- IP issuer configuration uses the existing pinned Caddy2.11.9 ACME `profile=shortlived`. The gateway derives its connection policy from its owned certificate subjects: no IP -> `[{}]`; one IPv4 -> `[{default_sni:IP}]`; more than one IP rejects before load because IP clients omit SNI. DNS-only existing issuer and connection policies remain byte-identical. Existing config fields suffice.
- Backup credentials/recovery passwords remain private and outside source archives. Public readiness still requires an actual encrypted off-host capture, full restore validation and all API routes. Recovery targets must be empty, and captured sessions must be revoked. Never roll old data over a potentially admitted application.
